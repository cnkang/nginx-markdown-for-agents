# Release Notes: 0.9.4

**Status**: Pending release. This document describes the 0.9.4 release
candidate and does not assert that a tag or checksum exists.

The latest public stable release remains v0.9.3. The v0.9.4 assets become
available only after publication and maintainer approval of the exact
candidate SHA.

**Compatibility target**: Non-breaking. The 20 active directives and their
defaults, HTTP representation, metrics and diagnostics, reason codes, and the
Rust/C FFI ABI version 3 remain unchanged.

---

## Summary

The 0.9.4 candidate prepares module artifacts for current NGINX builds and
Ubuntu's patched NGINX package revisions. NGINX owns its upstream security
fixes. This module release does not claim to fix an NGINX vulnerability. It
lets users install a module built for the NGINX revision they run after
upgrading NGINX.

## Candidate compatibility targets

| Channel | Target | Architectures and libc | Candidate evidence state |
|---|---|---|---|
| nginx.org stable | 1.30.7 | amd64 and arm64, glibc and musl | Verified in CI; final release gate blocked |
| nginx.org mainline | 1.31.9 | amd64 and arm64, glibc and musl | Verified in CI; final release gate blocked |
| Ubuntu 24.04 LTS native | `1.24.0-2ubuntu7.20` | amd64 and arm64 | Verified in CI; final release gate blocked |
| Ubuntu 26.04 LTS native | `1.28.3-2ubuntu1.13` | amd64 and arm64 | Verified in CI; final release gate blocked |

The CI evidence in `docs/evidence/0.9.4/compat/` records all 40 blocking rows
from run [44641110009](https://github.com/cnkang/nginx-markdown-for-agents/actions/runs/44641110009)
at commit `637c5992d9221dafcca2d77f86c5b82fc2e4a778`. The promotion tool marked
36 module and package rows verified. The four official Docker rows have
successful same-run evidence but retain `pending` matrix state because the
promotion tool does not manage `docker-image` rows. The Ubuntu records confirm
the installed package revision, ABI provide, Brotli dependency, and
incompatible module rejection on each architecture.

GitHub blocked the run's Release Gate before runner startup because the protected
`release-signing` environment allows deployments only from `main` and tag
`v0.9.3`. The final candidate SHA has not passed a complete rehearsal. The
workflow produced no release manifest or `SHA256SUMS`. This candidate is not
ready for publication.

NGINX published the 1.30.7 stable and 1.31.9 mainline releases on 2026-11-18
([official release announcement](https://nginx.org/index.html)). Ubuntu
published the package revisions above in [USN-9159-1](https://ubuntu.com/security/notices/USN-9159-1).
These upstream changes are not vulnerabilities in this module.

## Packages and compatibility contracts

nginx.org builds and Ubuntu-native builds are separate products. The former
targets the matching nginx.org binary and produces the module archive and
DEB/RPM package families required by the release contract. The latter builds
against Canonical's source package and binary, records the Ubuntu ABI provide,
and produces `nginx-module-markdown-for-agents-ubuntu` DEBs. Do not substitute
one package family for the other.

The release preserves all v0.9.3 tags, assets, and evidence. It also keeps
Homebrew support experimental.

## Publication

This file is a candidate note, not publication confirmation. Before release,
the maintainer must approve the exact candidate SHA and publication date. The
protected `release-signing` workflow must then publish the tag and signed
checksums. Until that approval and publication, use the v0.9.3 assets.
