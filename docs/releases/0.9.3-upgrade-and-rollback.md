# 0.9.3 Upgrade and Rollback

This note is the release-level summary for operators. The detailed procedures
are in the linked guides.

## Upgrade

1. Read the target platform in the support matrix.
2. Choose the artifact family: nginx.org or Ubuntu-native.
3. Verify the checksum.
4. Install the package.
5. Run `nginx -t`.
6. Reload NGINX.
7. Confirm one Markdown response and one HTML response.

The full procedure is in [UPGRADE-TO-0.9.3.md](../guides/UPGRADE-TO-0.9.3.md).

## Rollback

A matching ABI is necessary, but it does not prove compatibility across package
revisions. Use the exact verified NGINX revision, or rebuild and verify the module.
Run `sudo nginx -t` before reloading. An ABI change requires a matching rebuild
or restoration of the previous NGINX package.

The full procedure is in
[VERSION_ROLLBACK-0.9.3.md](../guides/VERSION_ROLLBACK-0.9.3.md).

## What changes for an operator

- The 20 active directives, their defaults, and the response contracts stay
  the same.
- The Ubuntu-native package is a new artifact family. It is not the nginx.org
  package.
- APT can retain old NGINX packages or propose removal of an incompatible module.
  Module removal does not remove user configuration. Disable all module
  directives before testing NGINX without the module.
  Follow the backup and conflict procedure in the Ubuntu guide.

## Timing

The 0.9.3 release candidate is for pilot testing before publication. Use the
release-tag artifacts after publication. Run a pilot on a non-critical host
before a fleet upgrade.
