# Release Notes: 0.9.3

**Target release date**: TBD (at release)

**Compatibility target**: Non-breaking. 0.9.3 is a compatibility maintenance
release. It does not add, remove, rename, or re-default a module directive. It
does not change the HTTP representation, the metrics contract, the diagnostics
document, the reason-code registry, or the Rust/C FFI ABI. ABI version 3 stays
current.

**Status**: Pending release. 0.9.3 is not yet published. Use the release-tag
downloads after publication.

---

## Summary

0.9.3 makes the current nginx.org stable and mainline releases first-class
supported targets. It adds Ubuntu 24.04 and Ubuntu 26.04 native NGINX to the
supported surface, using Canonical's source package and Canonical's ABI. It
also adds an evidence-gated promotion path, so a version can become supported
only together with recorded build, load, and request evidence.

The release exists because v0.9.2 shipped before nginx.org published 1.30.6
and 1.31.8. The v0.9.2 matrix therefore treated those versions as best-effort.
The same release carried no distro-native Ubuntu artifact.

## Highlights

### Current nginx.org releases are supported and release blocking

- The project supports stable 1.30.6 and mainline 1.31.8 for glibc and musl,
  on amd64 and arm64.
- Each target has a build-and-load gate in the release workflow. A failure
  blocks publication.
- Superseded patches 1.30.4, 1.30.5, and 1.31.6 keep their rows and their
  published assets. They no longer block a release. The v0.9.2 assets stay
  available for deployments that still run those patches.

### Ubuntu LTS native support

- A module builds from the Ubuntu source package for the installed NGINX
  revision, with the configure arguments that the Ubuntu binary reports.
- The supported releases are Ubuntu 24.04 LTS (`1.24.0-2ubuntu7.19`,
  `nginx-abi-1.24.0-1`) and Ubuntu 26.04 LTS (`1.28.3-2ubuntu1.12`,
  `nginx-abi-1.28.3-1`), on amd64 and arm64.
- A new package, `nginx-module-markdown-for-agents-ubuntu`, depends on the
  Ubuntu ABI virtual package. When a security update changes the ABI, apt
  cannot keep the module installed, and NGINX starts without the filter.
- The Ubuntu build links the distribution Brotli decoder and requires the
  revision that contains the fix for CVE-2026-111497.

See [UBUNTU-LTS-NGINX-COMPATIBILITY.md](../guides/UBUNTU-LTS-NGINX-COMPATIBILITY.md).

### Evidence-gated promotion

- A new promotion tool changes a matrix row only when a valid evidence record
  covers that row.
- A new validator rejects a `verified` row without a matching record. It also
  rejects a record with a failed or skipped test.
- The weekly discovery workflow keeps its rule: a new version enters as
  best-effort and pending.
- Regression tests prove that discovery does not downgrade a promoted row and
  does not rewrite a fixed distribution row.

See [COMPATIBILITY-SUPPORT-POLICY.md](../guides/COMPATIBILITY-SUPPORT-POLICY.md).

### Packaging and checksums

- `packaging/checksums.sha256` contains the SHA-256 values for
  `nginx-1.30.6` and `nginx-1.31.8`. The maintainer checked both tarballs
  against the nginx.org signing key before adding the values.
- The checksum file also contains the nFPM `linux-arm64` binary, so the
  package step runs on arm64 runners.

## Upgrade

1. Read the support matrix for your platform:

   ```bash
   python3 tools/render_release_matrix_docs.py --release-notes
   ```

2. Install the artifact for your exact NGINX version. The nginx.org package
   and the Ubuntu-native package are different artifacts. Do not mix them.

3. Run the doctor:

   ```bash
   bash tools/doctor/nginx-markdown-doctor.sh
   ```

4. Test and reload NGINX:

   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

See [UPGRADE-TO-0.9.3.md](../guides/UPGRADE-TO-0.9.3.md) for the full
procedure.

## Known Limitations

- Ubuntu moves package revisions. A revision newer than the verified one needs
  a new build and a new load test before the project claims support for it.
- The Ubuntu-native package exists for amd64 and arm64 only.
- A rollback across an NGINX ABI change is not possible. Keep the previous
  package file for a same-ABI rollback.
- The Homebrew formula stays experimental and tracks an older NGINX version.
- The CI job that runs the contract gates keeps the display name
  `0.9.2 Contract Gates`. The name is part of the protected branch required
  checks. Renaming it needs a coordinated branch-protection change, so this
  release does not rename it.

## Verification

The release evidence records every verified target under
`docs/evidence/0.9.3/compat/`. Each record names the source revision, the
module checksum, the configure argument digest, the test list, and the workflow
run.

The gates for the release candidate are:

```bash
make test-all
make docs-check
make release-matrix-check
make compatibility-evidence-check
make release-gates-check-093
```

## Artifacts

The release publishes these families:

- DEB and RPM packages built against nginx.org releases.
- Dynamic module tarballs for glibc and musl, amd64 and arm64.
- Ubuntu-native DEB packages built against the Canonical package, for 24.04
  and 26.04, amd64 and arm64.
- `SHA256SUMS`, `SHA256SUMS.asc`, and `release-manifest.json`.

The release-page asset list is the authority for a given tag.
