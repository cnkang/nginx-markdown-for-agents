# Release Notes: 0.9.2

**Release date:** 2026-07-30

**Compatibility:** Non-breaking. All 0.9.1 configurations are valid under
0.9.2 without modification.

---

## Summary

nginx-markdown-for-agents 0.9.2 is a maintenance and hardening release that
fixes diagnostics and reason-code mapping gaps, adds OTel lifecycle cleanup,
introduces a dynconf rollback API, and establishes a public surface drift
detection gate for release integrity.

---

## Fixed

### Diagnostics `reason_to_code` Missing `bypass_no_transform` Mapping

The diagnostics endpoint's `reason_to_code` mapping table omitted the
`bypass_no_transform` reason code (numeric 25). Operators relying on the
diagnostics JSON to map reason strings to numeric codes could not resolve
this entry. The mapping is now complete.

### C Reason Code Constants Missing Decompression Series (4–11)

The C header defining reason code constants did not include the
decompression error series (codes 4–11: `decompression_error`,
`decompression_budget_exceeded`, `decompression_format_error`,
`decompression_truncated_input`, `decompression_io_error`, and the
related timeout/budget/replay codes). The Rust converter emitted these
codes, but the C module could not reference them by symbolic name.
All 12 reason code constants are now synchronized between Rust and C.

### `stream_state` `PRE_COMMIT` Fallthrough Logs Invariant Violation

The streaming backpressure state machine's `PRE_COMMIT` fallthrough path
previously advanced state silently. It now logs an invariant violation
at `ngx_log_error` level, improving debuggability for streaming edge
cases without changing runtime behavior.

---

## Added

### OTel Worker Lifecycle Cleanup on Reload/Shutdown

OpenTelemetry worker threads and associated resources are now properly
cleaned up during NGINX graceful reload and shutdown. Previously, repeated
reload cycles could accumulate leaked OTel worker state. This is transparent
to operators — no configuration change required.

### Dynconf Rollback API

A new rollback action is available on the diagnostics endpoint:

```bash
curl -X POST "http://localhost/nginx-markdown/diagnostics?action=rollback"
```

This reverts the active dynamic configuration to the previously applied
snapshot without restarting NGINX. One level of rollback is available.
See [DYNAMIC_CONFIG.md](../guides/DYNAMIC_CONFIG.md) for full usage.

### Public Surface Inventory and Drift Detection Gate

A new release gate validates that the public API surface — FFI exports,
configuration directives, metric names, and reason codes — has not drifted
from the declared inventory. This gate runs as part of
`make release-gates-check-092` and catches accidental surface changes
before they reach a release.

### Release Gates 0.9.2

The `release-gates-check-092` Make target provides the 0.9.2 release gate
chain, additive on 0.9.1 gates:

```bash
make release-gates-check-092
```

Includes all 0.9.1 gates plus the public surface drift detection gate.

## Upgrade

See [UPGRADE-TO-0.9.2.md](../guides/UPGRADE-TO-0.9.2.md) for detailed
upgrade instructions by deployment method.

**Quick upgrade (prebuilt module):**

```bash
# Back up current module
sudo cp /usr/lib/nginx/modules/ngx_http_markdown_filter_module.so \
    /usr/lib/nginx/modules/ngx_http_markdown_filter_module.so.0.9.1.bak

# Install 0.9.2 module
sudo cp ngx_http_markdown_filter_module-0.9.2.so \
    /usr/lib/nginx/modules/ngx_http_markdown_filter_module.so

# Validate and restart
sudo nginx -t && sudo systemctl restart nginx
```
