0.9.3 changes. It gives the rule subset, the exceptions, and the limits of the
check. It does not claim a third-party certification.

## 3. Rule subset and how the project checks it

| Rule area | Rule | Check |
|---|---|---|
| Sentence length, descriptive text | 6.3 (25 words) | `ste_audit.py`, automated |
| Sentence length, notes | 5.5 (25 words) | `ste_audit.py`, automated |
| Sentence length, procedures | 5.1 (20 words) | A reviewer counts each new step |
| One instruction per step | 5.2, 5.3 | Manual review |
| No semicolon in prose | 8.1 | `ste_audit.py`, automated |
| No contracted forms | 4.2 | `ste_audit.py`, automated |
| No Latin abbreviation | GR-6 | `ste_audit.py`, automated |
| Active voice | 3.6 | `check_writing_style.py --changed`, advisory |
| One topic per paragraph, at most six sentences | 6.6 | Manual review |
| Approved word and approved meaning | 1.1 to 1.4 | Manual review, no dictionary automation |
| Technical nouns and verbs | 1.5, 1.12 | Manual review |
| Multi-word noun length | 2.1 (three words) | Manual review |
| Article and demonstrative use | 4.4, 4.5 | Manual review |

The two automated checks run in the repository:

```bash
python3 /path/to/ste_audit.py docs/guides/*.md docs/releases/0.9.3-*.md
python3 tools/docs/check_writing_style.py --changed --base <base-sha>
```

`make docs-check` runs the second check as `docs-style-check-regression`.

## 4. Controlled terms and technical identifiers

The review keeps these items in their exact form. A dictionary substitution
would change a technical meaning or break a command.

- NGINX directive names: `markdown_filter`, `markdown_limits`,
  `markdown_error_policy`, and the other active names.
- Field and key names: `support_tier`, `release_blocking`,
  `verification_state`, `nginx_version`, `abi_version`.
- File names and paths: `packaging/checksums.sha256`,
  `tools/release-matrix.json`, `/etc/nginx/modules-enabled/`.
- Commands and options: `nginx -t`, `nginx -V`, `dpkg-query -W`,
  `apt-get source`, `--with-compat`, `--add-dynamic-module`.
- Versions, revisions, and digests: `1.30.6`, `1.24.0-2ubuntu7.19`,
  `nginx-abi-1.24.0-1`, `sha256:...`.
- Product names: NGINX, Ubuntu, Canonical, Brotli, nFPM, Rust, Cargo.
- HTTP terms: `Accept`, `Vary`, `Content-Type`, `text/markdown`, ETag, HEAD.

Technical nouns that the dictionary does not contain: package revision, ABI
provide, compatibility signature, workflow run, evidence record, support
tier, release gate. The documents use each term with one meaning and one form.

## 7. Accepted exceptions

| Item | Reason |
|---|---|
| Command blocks longer than 20 words | A shell command is one technical unit. The project does not split it to meet a word count |
| Technical identifiers inside a sentence | A path or a version counts as one token in the word count |
| Table cells with several short clauses | A table row is a reference record, not a procedure |
| Existing `CHANGELOG.md` history | Historical entries stay as written. Only the `[0.9.3]` entry is in scope |
| "must" in a requirement statement | The word states a requirement, not a possibility |

## 8. Unverified clauses

These items need a human review against the official dictionary. The project
does not claim that a machine check covers them.

- Word-level approval against the Part 2 dictionary (875 approved words and
  1274 not-approved words). The review used the approved-word list by hand for
  the words it changed, not for every word in every file.
- The passive-voice check is a heuristic. It flags patterns, and a writer
  decides.
- A reviewer counted the procedure sentences by hand. The automated audit
  applies the 25-word descriptive limit to all prose.
- A reviewer applied Rule 2.1 to the new terms by hand.

## 9. Conclusion

The changed English documents meet the measurable limits of the rule subset in
section 3. The review found no remaining semicolon, no contraction, no Latin
abbreviation, and no sentence over 25 words.

The documents are **not** certified to ASD-STE100. Certification needs a
qualified human review against Issue 9, including the full dictionary. The
status of this review is `pass with noted exceptions` for the rule subset, and
`needs-human-review` for the dictionary clauses in section 8.

## 10. Final safety review, 2026-10-31

The final review covers the Ubuntu compatibility, upgrade, rollback, support,
release notes, and release guidance changes.
The reviewer checked new instructions against the 20-word limit and descriptions
against the 25-word limit.
Each procedure uses explicit actions for backup, dependency review, configuration
validation, and recovery.
The documents distinguish an ABI identifier, an exact package revision, and
actual validation evidence.
They do not promise automatic package removal or successful service startup.

`make docs-check` passed after these changes with zero new style warnings.
The README language pair retains the same pending release status and support scope.
The dictionary limitations in section 8 still apply.
