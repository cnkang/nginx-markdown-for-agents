## Scope

Week 1 delivers two blocking capabilities and one packaging capability.

- W1-01: an immutable historical contract anchor for `v0.9.2` and `v0.9.4`.
- W1-02: a blocking cross-release comparison gate with negative fixtures.
- W1-03: prerelease-aware package versioning and a safe publication path.
- W1-04: documentation, results, and an RC readiness verdict.

The 1.0 line keeps these items out of scope, and this work does not change
them:

- a configuration V3,
- an FFI redesign,
- a streaming state-machine rewrite,
- new OpenTelemetry or dynamic-configuration surfaces,
- any reduction of the platform matrix.

## Design Decisions

### Anchors are committed manifests, and the gate re-derives them

Each anchor is a JSON manifest under `tools/compatibility/contracts/`. The
manifest records the tag, the tag object SHA, the commit SHA, the extractor
version, and a digest per contract surface.

`make compatibility-contract-check` performs three proofs.

1. The manifest file digest matches the digest recorded in `INDEX.json`.
2. The recorded commit equals the commit the tag resolves to today.
3. A fresh extraction from the tag reproduces the recorded contract digest.

A shallow checkout without tags fails the gate. It never passes by skipping
the proof.

### Five verdicts, and one of them is not a pass

The comparator returns `OK`, `ADDITIVE`, `REVIEW_REQUIRED`, `BREAKING`, or
`UNVERIFIED`. `BREAKING`, `REVIEW_REQUIRED`, and `UNVERIFIED` all block a bare
run. A missing surface is `UNVERIFIED`, never a pass.

An approval file can convert an exact `REVIEW_REQUIRED` finding to `OK`. It
never converts a `BREAKING` finding. The file must name the reviewer, the
reason, and the date.

### Tag-to-tag comparisons need a documented delta

The historical audit compares `v0.9.2` with `v0.9.4`. Every non-additive
finding must appear in the `documented_delta` list of `INDEX.json`, together
with a rationale. An observed delta that the list omits fails the gate, and a
listed delta that no longer occurs also fails. The record therefore describes
what changed instead of claiming a zero diff.

### The HTTP surface binds to executed tests

Static extraction cannot prove HTTP behavior. The manifest records the
contract test files and their digests, and the report names the target that
executes them. A change to a bound test yields `REVIEW_REQUIRED`, so a
behavioral edit cannot pass without a decision.

### Package families get their own version shape

The release identity stays SemVer. Each family maps it through
`packaging/scripts/release_version.py`.

| Version | Debian upstream | RPM version | RPM release |
|---------|-----------------|-------------|-------------|
| `0.9.4` | `0.9.4` | `0.9.4` | `nginx1.28.3.1` |
| `1.0.0-rc.1` | `1.0.0~rc1` | `1.0.0~rc1` | `nginx1.28.3.1` |
| `1.0.0` | `1.0.0` | `1.0.0` | `nginx1.28.3.1` |

The tilde is load bearing in both families. Debian sorts `1.0.0~rc1` below
`1.0.0` and above `0.9.4`. RPM sorts a numeric leading segment above a letter
segment, so a release-first marker such as `0.rc1` would sort above the
existing `nginx1.28.3.1` release. `rpmvercmp` confirms both statements, and
`packaging/tests/test-version-ordering.sh` asserts them.

### The legacy RPM workflow fails closed

`.github/workflows/release-rpm.yml` stays a compatibility workflow. It now
validates with `--stable-only`, so a prerelease cannot reach `rpmbuild`.

## File Ownership

The plan assigned areas so that shared surfaces stay serial.

| Area | Files | Integration rule |
|------|-------|------------------|
| Contract extraction and comparison | `tools/compatibility/**` | Main agent |
| Gate wiring | `Makefile`, `.github/workflows/ci.yml` | Main agent, serial |
| Version mapping and packaging | `packaging/scripts/release_version.py`, `packaging/scripts/validate-version.sh`, `packaging/nfpm/nfpm.yaml`, `packaging/rpm/SPECS/**` | Main agent, serial |
| Release workflow | `.github/workflows/release-packages.yml`, `.github/workflows/release-rpm.yml`, `.github/workflows/homebrew-tap-publish.yml` | Main agent, serial |
| Documentation | `docs/development/1.0.0-*`, `docs/project/VERSION_PLANNING.md` | Main agent |

No two writers touched the same file. The main agent executed every area.
A third-party design review ran through `codex` before the packaging edits, and
its findings changed the RPM decision.

## Dependencies

The gate depends on the extractor, the extractor depends on the tracked
contract sources, and the anchor manifests depend on both release tags being
reachable. The packaging work depends on the version mapper, and the release
workflow depends on the mapper plus the nFPM release variable.

| Dependency | Consumer | Failure mode when absent |
|------------|----------|--------------------------|
| `tools/compatibility/extract.py` | CLI, tests | Gate cannot start |
| `tools/compatibility/contracts/INDEX.json` | CLI | Gate fails closed |
| Release tags `v0.9.2`, `v0.9.4` | Anchor verification | Gate fails closed |
| `packaging/scripts/release_version.py` | Workflow, Makefile, gate 3 | Packaging fails before nFPM runs |
| `NFPM_RELEASE` | `packaging/nfpm/nfpm.yaml` | nFPM leaves the release empty |

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| GitHub immutable releases may require a draft before an asset upload | A prerelease publication could fail late | Recorded as a maintainer check in the readiness document |
| Release evidence paths embed the version, and a prerelease adds a `~` in some paths | A path check may reject `~` | Evidence paths use the release identity, and the package metadata keeps the family mapping |
| Some release validators require three numeric components | An RC candidate could fail a validator that runs only at release time | Listed as a required RC-candidate change in the readiness document |
| nFPM is absent on the developer host | Local package build not executed | Gate 3 and the release workflow exercise nFPM, and the ordering test uses real `dpkg` and `rpm` |
| Protected environment signing cannot run locally | Signing stays unverified here | Listed as a maintainer-executed step |
