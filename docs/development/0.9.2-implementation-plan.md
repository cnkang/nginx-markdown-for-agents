### Historical 0.9.1 Baseline

- Zero-copy streaming output (default off, experimental)
- Gzip + zlib/raw-deflate + Brotli streaming decompression
- Full-buffer copy reduction
- Performance evidence gates (release-gates-check-091)
- Install doctor (8 checks + artifact recommendation)
- ADRs 0020-0022
- Config V2 with reject-only legacy directives
- Dynconf dry-run and LKG
- OTel experimental surface (historical. Removed from the 0.9.2 production contract)
- 54 Prometheus metric families
- 27 reason codes
- 63 directives (44 active, 19 reject-only)
- FFI ABI version 2, 34 catch_unwind sites
- 1560 Rust tests, 127 C test files, 12 fuzz targets

### Known Limitations

- OTel is absent from the 0.9.2 production contract. The historical 0.9.1
  behavior documents only for migration and rollback context
- Dynconf has no runtime rollback API. Operators restore a valid watched file
  atomically, while LKG protects the active snapshot after failed reloads
- Streaming C-only reason codes use UPPERCASE (not in Rust enum)
- ADR-0006 declares protobuf but implementation uses JSON

## 2. Version Scope

### 0.9.2 Goals

1. Fix all P1 correctness gaps (diagnostics reason_to_code and reason registry)
2. Public surface source metadata and ABI drift gate
3. Finalize OTel surface disposition by removing the experimental directives
   and implementation from the production contract
4. Define safe dynconf file restore and reject worker-local rollback APIs
5. Create 0.9.2 release gates
6. Update all version metadata to 0.9.2
7. Create migration/upgrade/rollback documentation
8. Update packaging metadata (DEB changelog, RPM spec)
9. Synchronize C/Rust reason code surfaces
10. Verify and document all active directives as stable

### Non-Goals

- New product capabilities (LLM extraction, browser rendering, etc.)
- OTel ring buffer / batch export / protobuf (future additive)
- Streaming state machine rewrite
- Active directive renames
- New decompression formats
- Distributed control plane
- Remote SaaS dependencies

### Breaking Changes

0.9.2 is the **final breaking release before 1.0**: the configuration
surface drops from 63 directives to exactly 25. The release removes the 19
reject-only migration stubs entirely (they now produce NGINX's standard
`unknown directive` error instead of a migration hint). It also removes 14
active directives (profiles, OTel, per-path metrics, shadow mode, zero-copy
control, streaming threshold, stream-type allowlist, diagnostics allow-list,
token-estimation controls) and unifies 5 standalone limit directives
into the `markdown_limits key=value` syntax. The release renamed the streaming
reject action to `REJECT_STATUS` (internal symbol only). See
`docs/guides/0.9.2-breaking-changes.md` for the complete reference and
`docs/guides/MIGRATION-0.9.2.md` for before/after examples. The diagnostics
mutation contract is explicitly read-only: no worker-local runtime rollback
endpoint or response schema gets exposed.

### Stable Behavior (Unchanged)

- The 25 retained directives keep names, syntax, defaults, contexts
  (the frozen public surface documented in MIGRATION-0.9.2.md)
- FFI ABI version is 2
- All 27 reason codes keep discriminants and strings
- Streaming state machine unchanged
- Decompression paths unchanged
- URL/trusted proxy security model unchanged

### WI-3: OTel Surface Disposition

**Current**: The experimental OTel directives and implementation are not part
of the 0.9.2 production contract.

**Target**: Keep public documentation explicit that the module supplies tracing via
NGINX's native integration or an external observability layer. Do not claim
request-scoped export, worker lifecycle state, or shutdown flushing for this
module.

**Test**: The removed-directive rejection test covers the old configuration
names. The streaming lifecycle unit test covers the surviving request path.

**Decision**: The old request-scoped ownership discussion is historical only.
No OTel production lifecycle exists in 0.9.2.

**Status**: completed (surface removed)

### WI-5: Dynconf File Restore Contract

**Current**: The LKG snapshot saves (`last_known_good`, `lkg_valid`,
`lkg_mtime`) for diagnostics and failed-reload protection. A worker-local
restore endpoint would be unsafe because the watcher is worker-local.

**Target**: Remove the public rollback parser, CSRF path, response schema, and
runtime restore helper. Keep the internal LKG state, reject diagnostics POST
with 405, and document atomic temp-file replacement as the restore procedure.

**Files**:
- `components/nginx-module/src/ngx_http_markdown_dynconf_impl.h`
- `components/nginx-module/src/ngx_http_markdown_diagnostics.c`

**Test**: Assert the module rejects diagnostics POST and exercise valid/invalid
atomic file replacement through the dynconf reload test.

**Harness**: Rule 35 (dynconf snapshot race elimination, LKG behavior).

**Status**: completed (safe file restore, no public runtime rollback API)

The worker-consistency and atomic-replacement decision appears in
[ADR-0026](../architecture/ADR/0026-dynconf-file-restore-contract.md).
