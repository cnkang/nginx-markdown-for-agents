# 0.9.2 Implementation Plan

## 1. Baseline Information

- **Main commit SHA**: 409e3e068752579c67b72ec3fbc9fbf7faa6dcf5
- **Branch**: dev/wip-0.9.2 (created from main at above SHA)
- **Current version**: 0.9.1
- **Latest tag**: v0.9.1
- **Date**: 2026-07-30

### 0.9.1 Completed Capabilities

- Zero-copy streaming output (default off, experimental)
- Gzip + zlib/raw-deflate + Brotli streaming decompression
- Full-buffer copy reduction
- Performance evidence gates (release-gates-check-091)
- Install doctor (8 checks + artifact recommendation)
- ADRs 0020-0022
- Config V2 with reject-only legacy directives
- Dynconf dry-run and LKG
- OTel experimental surface (markdown_otel + markdown_otel_endpoint)
- 54 Prometheus metric families
- 26 reason codes
- 44 active directives, 14 reject-only directives
- FFI ABI version 1, 34 catch_unwind sites
- 1560 Rust tests, 127 C test files, 12 fuzz targets

### Known Limitations

- No Content-Encoding chain decompression (single encoding only)
- OTel lacks reload/shutdown lifecycle, ring buffer, batch export
- Dynconf rollback API not exposed (LKG saved but no restore endpoint)
- Streaming C-only reason codes use UPPERCASE (not in Rust enum)
- ADR-0006 declares protobuf but implementation uses JSON

## 2. Version Scope

### 0.9.2 Goals

1. Fix all P1 correctness gaps (diagnostics reason_to_code, OTel lifecycle)
2. Complete public surface inventory and drift gate
3. Finalize OTel surface disposition (upgrade to stable or clean incomplete surface)
4. Add dynconf rollback API
5. Create 0.9.2 release gates
6. Update all version metadata to 0.9.2
7. Create migration/upgrade/rollback documentation
8. Update packaging metadata (DEB changelog, RPM spec)
9. Synchronize C/Rust reason code surfaces
10. Verify and document all active directives as stable

### Non-Goals

- New product capabilities (LLM extraction, browser rendering, etc.)
- Content-Encoding chain decompression (design limitation, documented)
- OTel ring buffer / batch export / protobuf (future additive)
- Streaming state machine rewrite
- Active directive renames
- New decompression formats
- Distributed control plane
- Remote SaaS dependencies

### Breaking Changes

None planned. 0.9.2 is a stabilization release. All changes are additive
or corrective. The active directive set, defaults, and FFI ABI remain
unchanged.

### Stable Behavior (Unchanged)

- All 44 active directives keep names, syntax, defaults, contexts
- FFI ABI version remains 1
- All 26 reason codes keep discriminants and strings
- Profile defaults unchanged (C/Rust consistent)
- Streaming state machine unchanged
- Decompression paths unchanged
- URL/trusted proxy security model unchanged

## 3. Work Items

### WI-1: Fix Diagnostics reason_to_code Mapping

**Current**: `ngx_http_markdown_diagnostics_reason_to_code()` lacks
`bypass_no_transform` (discriminant 25). Returns -1 for this reason code.

**Target**: Add `bypass_no_transform` → 25 mapping to both lowercase and
legacy uppercase tables. Update comment range from 0..24 to 0..25.

**Files**:
- `components/nginx-module/src/ngx_http_markdown_diagnostics.c` (mapping table)
- `components/nginx-module/src/ngx_http_markdown_diagnostics.h` (comment)

**Test**: Add C unit test verifying all 26 reason codes map correctly.

**Harness**: Rule 7 (explicit skip-reason mapping), Rule 8 (format string
argument matching).

**Status**: pending

### WI-2: Synchronize C Reason Code Constants

**Current**: `ngx_http_markdown_reason.c` REASON_* defines only cover
discriminants 0-3 and 12-25, missing 4-11 (decompression series).

**Target**: Add REASON_DECOMPRESSION_ERROR(4) through
REASON_DECOMPRESSION_IO_ERROR(8) and REASON_TIMEOUT(9),
REASON_BUDGET_EXCEEDED(10), REASON_REPLAY_ERROR(11).

**Files**:
- `components/nginx-module/src/ngx_http_markdown_reason.c`

**Test**: Verify existing FFI-based string lookup still works.

**Status**: pending

### WI-3: OTel Lifecycle Management

**Current**: No init_worker/exit_worker hooks for OTel. Span data is
per-request (pool-allocated) but no worker-level cleanup on
reload/shutdown.

**Target**: Add `ngx_http_markdown_otel_exit_worker()` that:
- Logs count of in-flight spans (advisory)
- Resets OTel state to prevent stale references after reload

This is a safety cleanup, not a ring buffer or batch export feature.

**Files**:
- `components/nginx-module/src/ngx_http_markdown_otel_impl.h`
- `components/nginx-module/src/ngx_http_markdown_filter_module.c` (exit_worker hook)

**Test**: Add C unit test for exit_worker cleanup. Add E2E reload test
with OTel enabled.

**Decision**: Keep `markdown_otel` and `markdown_otel_endpoint` as
experimental in 0.9.2. They have complete span creation + W3C
propagation + OTLP/JSON export, but lack ring buffer, batch export,
and production soak. Promoting to stable requires these, which is 1.x
additive work.

**Status**: pending

### WI-4: OTel ADR-0006 Documentation Correction

**Current**: ADR-0006 declares OTLP HTTP/protobuf but implementation
uses OTLP JSON.

**Target**: Update ADR-0006 to reflect actual implementation (JSON).
Document protobuf as future consideration.

**Files**:
- `docs/architecture/ADR/0006-otel-integration.md`

**Status**: pending

### WI-5: Dynconf Rollback API

**Current**: LKG snapshot is saved (`last_known_good`, `lkg_valid`,
`lkg_mtime`) but no API to restore it. Code comments reference E04.2.

**Target**: Add `ngx_http_markdown_dynconf_rollback()` function that:
- Checks `lkg_valid`
- Copies LKG to active_snapshot
- Calls `dynconf_apply_snapshot()`
- Logs rollback event with reason
- Returns success/failure

Expose via diagnostics endpoint (POST to
`/nginx-markdown/diagnostics` with `action=rollback`).

**Files**:
- `components/nginx-module/src/ngx_http_markdown_dynconf_impl.h`
- `components/nginx-module/src/ngx_http_markdown_diagnostics.c`

**Test**: Add C unit test for rollback. Update E2E dynconf test.

**Harness**: Rule 35 (dynconf snapshot race elimination, LKG behavior).

**Status**: pending
