# v1.0.0-rc.1 Readiness

**Verdict: CONDITIONAL GO.**

This branch implements and verifies the compatibility gate and the
prerelease packaging path. Two classes of work remain, and a maintainer owns
both. The release identity has to move to `1.0.0-rc.1` and the release-time
evidence has to run on a frozen candidate. No blocking contract defect appeared
in Week 1.

This document does not announce a release. No tag exists, no GitHub Release
exists, and the work published no package.

tag run. Without it, the environment refuses every signing job before the
reviewer can approve it. Move the three GPG secrets into that environment so
other jobs cannot read them.

Release-time tools now share one SemVer grammar in `tools/lib/semver.py`. The
grammar accepts a prerelease suffix and rejects build metadata. The following
tools use it.

- `generate_release_gate_manifests.py`
- `generate_schema_artifacts.py`
- `generate_soak_scenario_manifest.py`
- `release_qualification_reuse.py`
- `validate_metrics_registry.py`
- `validate_release_metadata.py`
- `validate_schema_drift.py`
- `reason-codegen/generate.py`

The release-matrix normalizer now reads the release identity from the package
manifest. An artifact path can no longer drift from `Cargo.toml`.

The candidate stores its line artifacts under `artifacts/release/1.0.0-rc.1/`.
The local `make release-gates-check-094` target reads compatibility records
from `CANDIDATE_EVIDENCE_DIR`, which defaults to
`docs/evidence/1.0.0-rc.1/compat/`. Download the rehearsal's
`compat-evidence-*` artifacts outside the repository and pass that path. The
approved candidate commit therefore never changes to carry evidence. The
release workflow validates the current run's records directly and never reads
the checked-in directory.

```
bash tools/harness/detect_version_consistency.sh

    --version 1.0.0-rc.1 --phase candidate
```

A host without Docker reports the two install-level ordering checks as
`NOT_RUN`. `make release-gates-check-094` runs that target with
`REQUIRE_ALL=1`, so the full target needs a Docker-capable runner. On a host
without Docker, run the individual targets above.

## Publication State

A tag run validates the final phase. A prerelease identity keeps the candidate
status in that phase. The final phase requires a dated `CHANGELOG` entry, a
`Release candidate` status in `PROJECT_STATUS` and the release notes, and no
stable-release claim. The stable status applies to final releases only.

## Recommended Sequence

1. Land this branch and let the pull-request CI report on the compatibility
   job.
2. Finalize the candidate documents for the planned publication date. Date the
   `CHANGELOG` entry. Add the date and a `Release candidate` status to the
   release notes and `PROJECT_STATUS`. Update the unpublished notes in
   `README.md`, `README_zh-CN.md`, and `docs/guides/INSTALLATION.md`.
3. Validate the final metadata locally.

   ```
   python3 tools/release/gates/validate_release_metadata.py \
     --version 1.0.0-rc.1 --phase final
   ```

4. Push the candidate commit.
5. Dispatch the artifact-only rehearsal from that branch with
   `final_metadata=true`. A later documentation change creates a new SHA and
   needs a new rehearsal.
6. Download the compatibility records outside the repository, then run
   `make release-gates-check-094 CANDIDATE_EVIDENCE_DIR=<records>`. The
   candidate SHA does not change.
7. Freeze the rehearsed SHA in `RELEASE_APPROVED_CANDIDATE_SHA`.
8. Choose the signing path. A non-publishing dispatch path runs before the
   tag. Otherwise the tag push runs the signing job.
9. Create the tag at the frozen SHA, approve the environment, and publish.
10. Verify that the release carries the prerelease flag and is not marked
    latest.

### Rehearsal Dispatch

Push the candidate branch, then dispatch the canonical workflow from that ref.

```
gh workflow run release-packages.yml \
  --ref dev/wip-1.0.0-rc-candidate-identity \
  -f require_blocking=true \
  -f final_metadata=true
gh run list --workflow release-packages.yml --limit 1
gh run watch <run-id> --exit-status
```

The dispatch takes the release identity from `Cargo.toml` and never publishes
a GitHub Release. It runs without the `release-signing` environment.
`final_metadata=true` validates the dated candidate documents and requires
every blocking compatibility row.

### Signing Path

The `integrity-signing` job runs only for a tag push. No dispatch path signs a
package today. Choose one of two paths before the tag.

- Add a `signing_rehearsal` dispatch input that runs the signing job and never
  runs the publish job. Run it before the freeze.
- Sign during the tag push. The approved candidate SHA and the required
  environment reviewer gate that run, so the first signature is also the
  publication signature.

## Decision Statement

Week 1 supports a conditional go for `v1.0.0-rc.1`. The compatibility contract
is frozen, comparable, and enforced by a blocking gate. The packaging path
produces correctly ordered Debian and RPM versions for a prerelease. The
remaining work is release choreography that needs maintainer authority, not
further design.

The verdict becomes a full GO once B1 through B7 close and the candidate
carries the rehearsal evidence.
