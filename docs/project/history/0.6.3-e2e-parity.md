# Rust E2E Scenario Parity

This register maps compatibility shell entrypoints to their canonical Rust
scenario implementation. A migrated wrapper contains no product assertions. All
HTTP fixtures, requests, and assertions live in `tools/e2e-harness/`.
`tools/e2e/` remains the canonical entrypoint for shell scenarios that remain
unmigrated. Migrated wrappers may retain their compatibility name. They delegate
fixtures, requests, and assertions to `tools/e2e-harness/`.

| Compatibility entrypoint | Rust scenario | Covered behavior | Known gaps |
|---|---|---|---|
| `tools/e2e/verify_brotli_streaming_e2e.sh` | `tools/e2e-harness/src/scenarios/brotli_streaming.rs` (`brotli-streaming`) | Real module conversion for small and large Brotli responses; single-byte upstream chunks; streaming and full-buffer routing; automatic decompression disabled; budget fail-open; malformed, truncated, and trailing input safety; slow-reader backpressure and metrics | Build-disabled linkage is verified by the Ubuntu 22.04 CI build matrix because a running binary cannot toggle compile-time support |
| `tools/e2e/verify_accept_negotiation_e2e.sh` | `accept-negotiation` | Strict and force modes, wildcard, absent or malformed Accept, quality ordering, ties, and explicit rejection | Requires a module-enabled NGINX runtime |
| `tools/e2e/verify_metrics_endpoint_e2e.sh` | `metrics-endpoint` | Loopback metrics endpoint and bounded Prometheus output | Requires a module-enabled NGINX runtime |
| `tools/e2e/verify_conditional_requests_e2e.sh` | `conditional-requests` | ETag, weak and list validators, If-Modified-Since, empty 304 responses, Vary, and HEAD behavior | Requires a module-enabled NGINX runtime |
| `tools/e2e/verify_auth_cache_e2e.sh` | `auth-cache` | Authenticated conversion policy and cache-control rewriting | Requires a module-enabled NGINX runtime |
| `tools/e2e/verify_status_codes_e2e.sh` | `status-codes` | Configured reject statuses and response headers | Requires a module-enabled NGINX runtime |
| `tools/e2e/verify_error_handling_e2e.sh` | `error-handling` | Cases 1–3 cover valid, malformed, and empty HTML. Cases 4–6 cover upstream 500, 502, and 206 passthrough. Cases 7–8 cover conversion and fail-open on either side of the 64 KiB cap. | Raw captures use the harness artifact tree. The unused fail-closed route had no shell assertion. |
| `tools/e2e/verify_config_merge_e2e.sh` | `config-merge` | Cases 1 through 7 include the lettered cases and check directive precedence, passthrough, ETag and IMS. An invalid encoding also distinguishes inherited fail-open from a location-level reject. | Raw captures use the harness artifact tree. |
| `tools/e2e/verify_large_markdown_response_e2e.sh` | `large-response` | Static HTML passthrough, full-buffer Markdown and 30 requests at concurrency 3. The test checks all statuses and records the load summary. | Rust reports its own load measurements. |
| `tools/e2e/verify_streaming_failure_cache_e2e.sh` | `streaming-failure-cache` | Cases 10.1 through 10.13 include the lettered cases and cover response headers, precommit failure, aborted upstream, HEAD, 304 and authenticated cache policy. | The wrapper retains the plan and size override. |
| `tools/e2e/verify_encoding_chain_e2e.sh` | `encoding-chain` | Content-Encoding chain parsing and decompression routing | Requires a module-enabled NGINX runtime |
| `e2e-harness scenario smoke` | `smoke` | Runtime/bootstrap prerequisite and binary resolution checks | No former shell scenario wrapper; this is a harness-only prerequisite |

The Runtime Regressions CI job runs both entrypoints against the built NGINX
module. The Rust scenarios supersede the standalone Accept negotiation and
conditional request scripts in `tests/e2e/`.
