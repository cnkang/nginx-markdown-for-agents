### Promoted-cluster evidence procedure

Run the smoke against the candidate image, not a mutable `latest` tag. Replace
`<candidate-sha>` and `<candidate-image-repository>` with the full commit and
candidate image repository selected for the release:

```bash
set -euo pipefail
# KUBE_CONTEXT must name an existing kubectl context; fail early with
# guidance instead of letting helm/kubectl fail mid-procedure.
: "${KUBE_CONTEXT:?KUBE_CONTEXT must be set to the kubectl context for the gate4-promoted namespace}"
kubectl config get-contexts -o name | grep -qx "${KUBE_CONTEXT}" || {
  echo "ERROR: kubectl context '${KUBE_CONTEXT}' does not exist" >&2
  exit 1
}
candidate_sha="<candidate-sha>"
if [[ ! "${candidate_sha}" =~ ^[0-9a-fA-F]{40}$ ]]; then
  echo "candidate_sha must be a full 40-character hexadecimal commit SHA" >&2
  exit 1
fi
candidate_image_repository="<candidate-image-repository>"
module_path="<module-path-inside-image>"
evidence_dir="release-evidence/gate4/${candidate_sha}"
mkdir -p "${evidence_dir}"

# Resolve the multi-platform index to one immutable digest before deployment.
candidate_digest="$(docker buildx imagetools inspect \
  --format '{{.Manifest.Digest}}' \
  "${candidate_image_repository}:${candidate_sha}")"
[[ "${candidate_digest}" == sha256:* ]] || {
  echo "candidate image did not resolve to an immutable digest" >&2
  exit 1
}
printf '%s\n' "${candidate_digest}" > "${evidence_dir}/candidate-digest.txt"

helm upgrade --install gate4-promoted charts/nginx-markdown \
  --kube-context "${KUBE_CONTEXT}" \
  --namespace gate4-promoted --create-namespace \
  --set image.repository="${candidate_image_repository}" \
  --set image.tag="" \
  --set image.digest="${candidate_digest}" \
  --set image.pullPolicy=Always \
  --set markdown.enabled=true \
  --set markdown.loadModule="${module_path}" \
  --set metrics.enabled=true \
  --wait --timeout 180s
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  rollout status deployment/gate4-promoted --timeout=180s
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get deployment/gate4-promoted -o json > "${evidence_dir}/deployment.json"
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get pods -l app.kubernetes.io/instance=gate4-promoted -o json \
  > "${evidence_dir}/pods.json"
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  port-forward service/gate4-promoted 18080:80 \
  > "${evidence_dir}/port-forward.log" 2>&1 &
port_forward_pid=$!
trap 'kill "${port_forward_pid}" 2>/dev/null || true' EXIT

# Poll localhost:18080 until the forwarded port accepts connections. Check
# process liveness on every iteration so a dead port-forward cannot be
# mistaken for a slow startup. The probe runs inside if/then so its nonzero
# exit cannot trip `set -euo pipefail` before the diagnostic path executes.
ready=0
readiness_deadline=$(( $(date +%s) + 30 ))
while :; do
  if ! kill -0 "${port_forward_pid}" 2>/dev/null; then
    echo "port-forward exited before becoming ready" >&2
    exit 1
  fi

  now=$(date +%s)
  remaining=$(( readiness_deadline - now ))
  if (( remaining <= 0 )); then
    break
  fi
  curl_timeout=$(( remaining < 3 ? remaining : 3 ))
  if curl -s --connect-timeout "${curl_timeout}" \
      --max-time "${curl_timeout}" -o /dev/null \
      http://127.0.0.1:18080/; then
    ready=1
    break
  fi

  now=$(date +%s)
  remaining=$(( readiness_deadline - now ))
  if (( remaining <= 0 )); then
    break
  fi
  sleep_seconds=$(( remaining < 1 ? remaining : 1 ))
  sleep "${sleep_seconds}"
done
if [[ "${ready}" != 1 ]] || ! kill -0 "${port_forward_pid}" 2>/dev/null; then
  echo "port-forward not ready within 30s or process is no longer alive" >&2
  exit 1
fi

conversion_status="$(curl -s --max-time 10 -D "${evidence_dir}/conversion-headers.txt" \
  -o "${evidence_dir}/conversion-body.txt" \
  -w '%{http_code}' \
  --header 'Accept: text/markdown' \
  --data '<h1>Gate4 Fixture</h1><p>Known content</p>' http://127.0.0.1:18080/)"
grep -qi 'text/markdown' "${evidence_dir}/conversion-headers.txt" \
  && [[ "${conversion_status}" == "200" ]] \
  && grep -q 'Gate4 Fixture' "${evidence_dir}/conversion-body.txt" \
  || { echo "conversion probe failed" >&2; exit 1; }

metrics_status="$(curl -s --max-time 10 -D "${evidence_dir}/metrics-headers.txt" \
  -o "${evidence_dir}/metrics-body.txt" \
  -w '%{http_code}' \
  --header 'Accept: text/plain' http://127.0.0.1:18080/_markdown_metrics)"
grep -qi 'text/plain' "${evidence_dir}/metrics-headers.txt" \
  && [[ "${metrics_status}" == "200" ]] \
  && grep -qE '^nginx_markdown_requests_total' "${evidence_dir}/metrics-body.txt" \
  && diff <(grep -oE '^nginx_markdown_[a-z_]+' "${evidence_dir}/metrics-body.txt" | sed -E 's/_(bucket|sum|count)$//' | sort -u) \
          <(python3 -c "import json;print('\n'.join(sorted(m['name'] for m in json.load(open('schemas/metrics-v1.registry.json'))['metrics'])))") > /dev/null \
  || { echo "metrics probe failed: missing or non-registry metrics" >&2; exit 1; }

kill "${port_forward_pid}"
wait "${port_forward_pid}" 2>/dev/null || true
trap - EXIT
```

The promoted image reference must resolve to the candidate commit. Resolve
`<candidate-image-repository>:<candidate-sha>` to one immutable
multi-platform index digest first (or deploy that resolved digest directly).
Do not accept a free-form `published_digest` value as an independent input.
Then identify each Ready pod's platform and require its image ID to equal the
platform-specific manifest selected from that same index. The following script
checks every Ready pod, not just one, and records both digest levels:

```bash
set -euo pipefail
# Resolve the candidate tag to one immutable multi-platform index. This is
# the only trusted source for the expected index and platform manifest values.
candidate_image_repository="<candidate-image-repository>"
candidate_sha="<candidate-sha>"
if [[ ! "${candidate_sha}" =~ ^[0-9a-fA-F]{40}$ ]]; then
  echo "candidate_sha must be a full 40-character hexadecimal commit SHA" >&2
  exit 1
fi
candidate_ref="${candidate_image_repository}:${candidate_sha}"
index_digest="$(docker buildx imagetools inspect "${candidate_ref}" \
  | awk '$1 == "Digest:" { print $2; exit }')"
index_json="$(docker buildx imagetools inspect "${candidate_ref}" --raw)"
if [[ ! "${index_digest}" =~ ^sha256:[0-9a-f]{64}$ ]] \
  || [[ "$(jq -r 'has("manifests") and (.manifests | length > 0)' \
          <<<"${index_json}")" != "true" ]]; then
  echo "candidate image did not resolve to a multi-platform index" >&2
  exit 1
fi
ready_pods="$(kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get pods -l app.kubernetes.io/instance=gate4-promoted \
  -o json | jq -r '
    .items[]
    | select(.status.phase == "Running"
        and ([.status.conditions[] | select(.type == "Ready" and .status == "True")]
             | length > 0))
    | . as $pod
    | $pod.status.containerStatuses[]
    | select(.name == "nginx-markdown")
    | [$pod.metadata.name, $pod.spec.nodeName, .imageID]
    | @tsv')"
if [[ -z "${ready_pods}" ]]; then
  echo "no Ready pods found for gate4-promoted — cannot verify promoted image digest" >&2
  exit 1
fi
while IFS=$'\t' read -r pod_name node_name pod_image_id; do
  [[ -z "${pod_name}" ]] && continue
  platform="$(kubectl --context "${KUBE_CONTEXT}" get node "${node_name}" \
    -o jsonpath='{.status.nodeInfo.operatingSystem}/{.status.nodeInfo.architecture}')"
  platform_os="${platform%%/*}"
  platform_arch="${platform#*/}"
  manifest_digest="$(jq -r --arg os "${platform_os}" --arg arch "${platform_arch}" '
    [.manifests[]
      | select(.platform.os == $os and .platform.architecture == $arch)
      | .digest]
    | unique
    | if length == 1 then .[0] else empty end' <<<"${index_json}")"
  if [[ ! "${manifest_digest}" =~ ^sha256:[0-9a-f]{64}$ ]]; then
    echo "no unique platform manifest for ${pod_name} (${platform})" >&2
    exit 1
  fi
  # Normalize each pod-reported value so an image name prefix
  # (registry/repo@sha256:...) does not break exact equality.
  normalized="${pod_image_id##*@}"
  if [[ "${normalized}" != "${manifest_digest}" ]]; then
    echo "digest mismatch: pod ${pod_name} reports ${normalized}, expected ${manifest_digest} for ${platform}" >&2
    exit 1
  fi
  printf '%s\t%s\t%s\t%s\n' \
    "${pod_name}" "${platform}" "${index_digest}" "${manifest_digest}"
done <<< "${ready_pods}"
```

Assemble `cluster-smoke.json` from the
deployment, pod, and probe outputs. Its minimum schema is:

```json
{
  "schema_version": "gate4.cluster-smoke.v1",
  "candidate_sha": "<full-commit-sha>",
  "image": {
    "reference": "<candidate-image-repository>:<candidate-sha>",
    "index_digest": "sha256:<64-hex>",
    "ready_pod_manifests": [
      {
        "pod": "<pod-name>",
        "platform": "linux/amd64",
        "manifest_digest": "sha256:<64-hex>"
      }
    ]
  },
  "cluster": {"context": "<context>", "namespace": "gate4-promoted"},
  "rollout": {"status": "pass", "deployment": "gate4-promoted"},
  "probes": {"conversion": "pass", "accept": "pass", "metrics": "pass"},
  "observed_at": "<observed-at-UTC>"
}
```

`candidate_sha` must be a full commit SHA. The evidence must record the
immutable multi-platform index digest and the platform manifest digest matched
by each Ready pod. Every
rollout/probe status must be `pass`. Missing fields, digest mismatch, stale
candidate SHA, or any failed probe is a blocking fail. Run one negative check
per cycle: deploy or reference a deliberately wrong digest and confirm both
the pod comparison and `validate_cluster_smoke.py` reject it. The schema version is `gate4.cluster-smoke.v1`. Validate
every `cluster-smoke.json` with the executable validator at
`tools/release/gates/validate_cluster_smoke.py` before accepting the evidence:

```bash
python3 tools/release/gates/validate_cluster_smoke.py \
  release-evidence/gate4/<candidate-sha>/cluster-smoke.json
```

The validator enforces: required fields present, `candidate_sha` is a full
40-hex commit SHA, `image.index_digest` is a 64-hex SHA-256 digest, every
`ready_pod_manifests[].manifest_digest` is a 64-hex SHA-256 digest, the index
digest matches the candidate image reference, each recorded manifest matches
the Ready pod's platform-specific image ID, `cluster.namespace` is
`gate4-promoted`, `rollout.status` is `pass`, all three probe statuses are
`pass`, and `observed_at` is a recent ISO-8601 timestamp.

The F5 record at `release-evidence/gate4/<candidate-sha>/f5-assessment.md`
must identify the controller image/version, module ABI match, module injection
method, exact `load_module` configuration, test date, and operator decision
(`pass` or `fail`). It must link the tested candidate digest and include
conversion, `Accept`, reload/rollback, and failure-mode results. A missing
field, untested candidate, ABI mismatch, or unresolved limitation is a
blocking fail. Do not infer the record from the feasibility guide alone. The
record must contain these headings: `Candidate`, `Controller`,
`Module and ABI`, `Injection`, `Verification`, `Rollback`, and `Decision`.
`Decision` is `pass` only when every listed verification and rollback check
passes. Set it to `fail` for an untested or unresolved limitation.

The F5 evidence has a maximum age: the `test date` must be within 14 days of
the Gate 4 acceptance review, and the `Candidate` digest must equal the
selected candidate digest. Before Gate 4 acceptance, run the current
candidate-bound release evidence gate with the resolved digest and acceptance
date:

```bash
make release-evidence-manifest-check
```

The project retired the former standalone F5 validator. The current manifest
gate binds release evidence to the delivered candidate and fails on stale or
mismatched records. The historical F5 headings and acceptance criteria above
remain part of this release record.

## Go/No-Go Decision

| Gate | Owner | Decision Point | Criteria |
|------|--------|-----------|------|
| Gate 1 | Module developer | After Phase 0 completion | All PASS |
| Gate 2 | Module developer | After Phase 1 completion | All PASS |
| Gate 3 | Platform engineer | After Phase 2 completion | All PASS |
| Gate 4 | Platform engineer | After Phase 3 completion | All PASS |
| Gate 5 | Full team | After Phase 4 completion | All PASS |
| Gate 6 | Release engineer | After fuzz/packaging integration | All PASS |

**Final Go**: 0.7.0 release blocking scope is Gates 1 through 6 as defined
above. Gate 3 is complete only when the DEB/RPM builds and signatures,
metadata, ABI dependencies, install smoke, upgrade/rollback, checksums,
install-layout, and documentation checks pass. Gate 4 is complete only when
Helm lint/render, manifest dry-run, promoted cluster smoke, custom image, and
F5 assessment checks pass. Gate 5 and Gate 6 remain blocking for their full
listed check sets, including harness/docs/release validators and fuzz/package
infrastructure. The release process must promote live cluster smoke and F5
evidence for a tag before reviewers can call them final Go criteria. The
release record must also contain the signed gate-review artifact naming the
reviewer, date, candidate, scope, and evidence references. Verification is
fail-closed: with an independently authenticated `TRUSTED_FINGERPRINT`, run
the equivalent of
`set -o pipefail; SIGNER_FINGERPRINT=$(gpg --batch --status-fd=1 --verify gate-review.md.asc gate-review.md 2>/dev/null | awk '$2 == "VALIDSIG" { print toupper($3); exit }'); test "$SIGNER_FINGERPRINT" = "$TRUSTED_FINGERPRINT"`.
The artifact is not accepted when GPG fails, emits no `VALIDSIG`, or names a
different signer.
