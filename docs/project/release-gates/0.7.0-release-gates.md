### Promoted-cluster evidence procedure

Run the smoke against the candidate image, not a mutable `latest` tag. Replace
`<candidate-sha>` and `<candidate-image-repository>` with the full commit and
candidate image repository selected for the release:

```bash
set -euo pipefail
candidate_sha="<candidate-sha>"
candidate_image_repository="<candidate-image-repository>"
module_path="<module-path-inside-image>"
evidence_dir="release-evidence/gate4/${candidate_sha}"
mkdir -p "${evidence_dir}"

helm upgrade --install gate4-promoted charts/nginx-markdown \
  --kube-context "${KUBE_CONTEXT}" \
  --namespace gate4-promoted --create-namespace \
  --set image.repository="${candidate_image_repository}" \
  --set image.tag="${candidate_sha}" \
  --set image.pullPolicy=Always \
  --set markdown.enabled=true \
  --set markdown.loadModule="${module_path}" \
  --set metrics.enabled=true \
  --wait --timeout 180s
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  rollout status deployment/gate4-promoted --timeout=180s
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get deployment/gate4-promoted -o json > "${evidence_dir}/deployment.json"
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get pods -l app.kubernetes.io/instance=gate4-promoted -o json \
  > "${evidence_dir}/pods.json"
kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  port-forward service/gate4-promoted 18080:80 \
  > "${evidence_dir}/port-forward.log" 2>&1 &
port_forward_pid=$!
trap 'kill "${port_forward_pid}" 2>/dev/null || true' EXIT

# Poll localhost:18080 until the forwarded port accepts connections
timeout 30 sh -c 'while ! curl -s -o /dev/null http://127.0.0.1:18080/; do sleep 1; done'
if ! curl -s -o /dev/null http://127.0.0.1:18080/; then
  echo "port-forward not ready within 30s — investigate before continuing" >&2
  exit 1
fi

conversion_status="$(curl -s --max-time 10 -D "${evidence_dir}/conversion-headers.txt" \
  -o "${evidence_dir}/conversion-body.txt" \
  -w '%{http_code}' \
  --header 'Accept: text/markdown' \
  --data '<h1>Gate4 Fixture</h1><p>Known content</p>' http://127.0.0.1:18080/)"
grep -qi 'text/markdown' "${evidence_dir}/conversion-headers.txt" \
  && [[ "${conversion_status}" == "200" ]] \
  && grep -q 'Gate4 Fixture' "${evidence_dir}/conversion-body.txt" \
  || { echo "conversion probe failed" >&2; exit 1; }

metrics_status="$(curl -s --max-time 10 -D "${evidence_dir}/metrics-headers.txt" \
  -o "${evidence_dir}/metrics-body.txt" \
  -w '%{http_code}' \
  --header 'Accept: text/plain' http://127.0.0.1:18080/_markdown_metrics)"
grep -qi 'text/plain' "${evidence_dir}/metrics-headers.txt" \
  && [[ "${metrics_status}" == "200" ]] \
  && grep -qE '^nginx_markdown_requests_total' "${evidence_dir}/metrics-body.txt" \
  && diff <(grep -oE '^nginx_markdown_[a-z_]+' "${evidence_dir}/metrics-body.txt" | sed -E 's/_(bucket|sum|count)$//' | sort -u) \
          <(python3 -c "import json;print('\n'.join(sorted(m['name'] for m in json.load(open('schemas/metrics-v1.registry.json'))['metrics'])))") > /dev/null \
  || { echo "metrics probe failed: missing or non-registry metrics" >&2; exit 1; }

kill "${port_forward_pid}"
trap - EXIT
```

The promoted image reference must resolve to the candidate commit: extract the
image digest from every Ready pod in the deployment and require each to equal the
digest published for `<candidate-sha>`. The following script checks all Ready
pods, not just one:

```bash
set -euo pipefail
published_digest="<published-digest-for-candidate-sha>"
ready_pods=$(kubectl --context "${KUBE_CONTEXT}" -n gate4-promoted \
  get pods -l app.kubernetes.io/instance=gate4-promoted \
  -o json | jq -r '[.items[] | select(.status.phase=="Running" and ([.status.conditions[] | select(.type=="Ready" and .status=="True")] | length > 0)) | .status.containerStatuses[0].imageID] | .[]')
if [[ -z "${ready_pods}" ]]; then
  echo "no Ready pods found for gate4-promoted — cannot verify promoted image digest" >&2
  exit 1
fi
for pod_digest in ${ready_pods}; do
  if [[ "${pod_digest}" != *"${published_digest}"* ]]; then
    echo "digest mismatch: pod reports ${pod_digest}, expected ${published_digest}" >&2
    exit 1
  fi
done
```

Assemble `cluster-smoke.json` from the
deployment, pod, and probe outputs. Its minimum schema is:

```json
{
  "schema_version": "gate4.cluster-smoke.v1",
  "candidate_sha": "<full-commit-sha>",
  "image": {"reference": "<repository>:<candidate-sha>", "digest": "sha256:<64-hex>"},
  "cluster": {"context": "<context>", "namespace": "gate4-promoted"},
  "rollout": {"status": "pass", "deployment": "gate4-promoted"},
  "probes": {"conversion": "pass", "accept": "pass", "metrics": "pass"},
  "observed_at": "2026-05-29T00:00:00Z"
}
```

`candidate_sha` must be a full commit SHA, the image digest must be a
64-hex SHA-256 digest, and every rollout/probe status must be `pass`.
Missing fields, digest mismatch, stale candidate SHA, or any failed probe is a
blocking fail. The schema version is `gate4.cluster-smoke.v1`. Validate
every `cluster-smoke.json` with the executable validator at
`tools/release/gates/validate_cluster_smoke.py` before accepting the evidence:

```bash
python3 tools/release/gates/validate_cluster_smoke.py \
  release-evidence/gate4/<candidate-sha>/cluster-smoke.json
```

The validator enforces: required fields present, `candidate_sha` is a full
40-hex commit SHA, `image.digest` is a 64-hex SHA-256 digest, the digest
matches the candidate image reference, `cluster.namespace` is `gate4-promoted`,
`rollout.status` is `pass`, all three probe statuses are `pass`, and
`observed_at` is a recent ISO-8601 timestamp.

The F5 record at `release-evidence/gate4/<candidate-sha>/f5-assessment.md`
must identify the controller image/version, module ABI match, module injection
method, exact `load_module` configuration, test date, and operator decision
(`pass` or `fail`). It must link the tested candidate digest and include
conversion, `Accept`, reload/rollback, and failure-mode results. A missing
field, untested candidate, ABI mismatch, or unresolved limitation is a
blocking fail. Do not infer the record from the feasibility guide alone. The
record must contain these headings: `Candidate`, `Controller`,
`Module and ABI`, `Injection`, `Verification`, `Rollback`, and `Decision`.
`Decision` is `pass` only when every listed verification and rollback check
passes. Set it to `fail` for an untested or unresolved limitation.

**Final Go**: 0.7.0 release blocking scope is Gates 1 through 6 as defined
above. Gate 3 is complete only when the DEB/RPM builds and signatures,
metadata, ABI dependencies, install smoke, upgrade/rollback, checksums,
install-layout, and documentation checks pass. Gate 4 is complete only when
Helm lint/render, manifest dry-run, promoted cluster smoke, custom image, and
F5 assessment checks pass. Gate 5 and Gate 6 remain blocking for their full
listed check sets, including harness/docs/release validators and fuzz/package
infrastructure. The release process must promote live cluster smoke and F5
evidence for a tag before reviewers can call them final Go criteria.
